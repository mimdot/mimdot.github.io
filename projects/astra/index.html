Your academic constellation

Older builds stay downloadable: v1.1.0 · v1.0.1 · v1.0.0 · all releases. Every published release keeps its files for good, so a link you have saved will keep working.

Or clone and run

git clone https://github.com/mimdot/CIK.git
cd CIK
./run.sh          # Windows: .\run.ps1

Builds whatever is missing, then launches. Windows needs Python 3.12+, Node 20+, Rust (MSVC) and the Visual C++ build tools — see docs/WINDOWS.md.

Desktop app sign-in is your email plus the shared access code 1819. It is a front door, not a security boundary.

What it does

Academic openings are scattered across faculty pages, mailing lists and PDF calls. Astra collects them, matches them to your field and stage, and shows you who supervises what — so the search becomes a shortlist you can act on.

Positions
From academic job boards, deduplicated and freshness-filtered.
Supervisors
Ranked by an explainable 0–100 fit, from NASA ADS, OpenAlex and arXiv. A search names each candidate as it is verified, can be stopped mid-run, and says so when a source is rate-limiting rather than quietly returning nothing.
Scored to your field
An editable per-field keyword taxonomy.
Saved items
Survive a re-crawl, with notes and an application status.
Yours alone
CV parsing stays local by default, and nothing is sent to a third party without opt-in.

Three ways to run it

Astra CLI

The aggregator and supervisor finder. Writes CSV, JSON and a self-contained HTML report.

python astra.py

Astra Dashboard

The local web app: a Next.js frontend on a FastAPI backend, both on localhost.

uvicorn api.app:app

Astra Desktop

The packaged app: a Tauri shell with the engine and its Python runtime bundled. Works offline.

./run.sh

Fields supported today

Sixteen field profiles ship with Astra — five of them new in v1.1.0. A profile is the editable knowledge for a subject — its anchor terms, context terms, negative terms and weights — and it decides which boards a run visits and how every result is scored.

Your subject missing? Adding one is a single YAML file and no Python: python astra.py --new-field marine_biology scaffolds it from a commented template.

What comes next

Planned, in roughly this order. The wider taxonomy has started — five fields landed in v1.1.0; the rest is not shipped yet.

01

Master's programmes as a live position type

Funded master's calls searched and scored alongside PhD and postdoc positions.

02

More listing sources

New boards and faculty feeds in the engine, so a run covers more of what is actually posted.

03

A wider field taxonomy started

Neuroscience, biomedical sciences, environmental science, materials science and statistics & data science shipped in v1.1.0, taking the taxonomy from 11 to 16. Still to come: the social sciences and humanities, and finer subfields throughout.

04

A scholarships crawler

Funding calls and deadlines for the twenty most common destination countries.

05

A scientific events crawler

Seminars, conferences and online events, with their registration and abstract deadlines.

The CLI and the dashboard run anywhere Python 3.12+ does. (3.12 is a floor, not a preference: the engine uses PEP 701 f-strings, which are a syntax error on 3.11.) The desktop app is built for all three platforms by CI from the same source; Ubuntu and Windows 11 have both been built and run, macOS has not. Windows was tested as a from-source build rather than the packaged installer — if you try one, please open an issue.

No server needed

A CLI run writes astra_positions.html next to its CSV and JSON: one self-contained file with the whole result set, openable from disk and publishable as a static page. This project page is static too, plain HTML on the site stylesheet, with every download a direct GitHub URL.

python astra.py --field astronomy

astra_positions.csv
astra_positions.json
astra_positions.html   # open it in a browser
